# Test Coverage

Test coverage tracking for all DatingApp microservices using Coverlet.

## Quick Start

### Collect Coverage Locally

```bash
# Run all tests with coverage
./collect-coverage.sh

# Generate HTML reports
./generate-coverage-report.sh

# View report
open coverage/report/index.html  # macOS
xdg-open coverage/report/index.html  # Linux
```

### Individual Service Coverage

```bash
cd photo-service
dotnet test \
  --collect:"XPlat Code Coverage" \
  --results-directory ./coverage

# View raw coverage file
find coverage -name "coverage.cobertura.xml"
```

## CI/CD Integration

Coverage is automatically collected in GitHub Actions:

1. **Test Execution** - Each service runs tests with coverage collection
2. **Summary Generation** - Line and branch coverage % added to workflow summary
3. **Codecov Upload** - Coverage data uploaded to Codecov (if token configured)

### Workflow Steps

```yaml
- name: Run unit tests with coverage
  run: dotnet test --collect:"XPlat Code Coverage"

- name: Generate coverage summary
  # Extracts coverage % from cobertura.xml
  # Adds to GitHub Actions summary

- name: Upload coverage to Codecov
  uses: codecov/codecov-action@v4
  # Uploads to codecov.io (requires CODECOV_TOKEN secret)
```

### Viewing CI Coverage

1. Go to GitHub Actions run
2. Click on workflow job (e.g., "Build & Test UserService")
3. Scroll to bottom of summary - coverage % shown

## Coverage Thresholds

**Recommended minimum coverage:**
- Line Coverage: 80%
- Branch Coverage: 70%

**Current approach:** Informational only (does not fail builds)

To enforce thresholds, add to test projects:

```xml
<PropertyGroup>
  <CoverletOutputFormat>cobertura</CoverletOutputFormat>
  <Threshold>80</Threshold>
  <ThresholdType>line,branch</ThresholdType>
  <ThresholdStat>total</ThresholdStat>
</PropertyGroup>
```

## Interpreting Coverage

### Line Coverage

Percentage of executable lines executed during tests.

**Good coverage:** 80%+
- Most code paths tested
- Core business logic validated
- Edge cases covered

**Low coverage:** <60%
- Missing test scenarios
- Untested error handling
- Review test quality

### Branch Coverage

Percentage of decision branches (if/else, switch) exercised.

**Good coverage:** 70%+
- Both true/false paths tested
- Switch cases covered
- Error conditions validated

**Low coverage:** <50%
- Missing negative test cases
- Incomplete conditional testing

## Excluding Code from Coverage

Use `ExcludeFromCodeCoverage` attribute:

```csharp
using System.Diagnostics.CodeAnalysis;

[ExcludeFromCodeCoverage]
public class Program
{
    public static void Main(string[] args) { }
}

[ExcludeFromCodeCoverage]
public class Startup
{
    // DI configuration - hard to unit test
}
```

**Appropriate exclusions:**
- Entry points (Program.cs, Main)
- DI configuration (Startup.cs)
- Auto-generated code
- Simple DTOs with no logic

**Avoid excluding:**
- Controllers
- Service classes
- Business logic
- Validation code

## Troubleshooting

### No Coverage Data Generated

**Symptom:** `coverage/` directory is empty

**Solution:**
1. Verify coverlet.collector is installed: `dotnet list package | grep coverlet`
2. Check test execution completed: `dotnet test --verbosity detailed`
3. Ensure tests actually run (not skipped)

### reportgenerator Command Not Found

**Symptom:** `./generate-coverage-report.sh` fails

**Solution:**
```bash
dotnet tool install -g dotnet-reportgenerator-globaltool
export PATH="$PATH:$HOME/.dotnet/tools"
```

### Coverage Percentages Seem Wrong

**Symptom:** Coverage lower than expected

**Check:**
1. Skipped tests don't generate coverage
2. Integration tests may mock dependencies
3. Code in bin/obj not counted
4. Attribute-excluded code not counted

## Scripts Reference
